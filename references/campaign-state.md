# Campaign 状态与持久化档案

首次建立 Campaign、处理后续回合、更新长期状态或回答历史问题时读取本文件。

## 档案位置

用户指定位置时使用用户的位置。否则，长模组或明确要求长期维护时，在当前工作区内建立：

```text
dnd-campaigns/<campaign-slug>/
├── campaign-profile.md
├── campaign-ledger.md
├── exports/
│   ├── session-001.docx
│   ├── session-001.pdf
│   └── session-001.txt        # 仅在用户要求时
├── sources/
│   ├── session-001/
│   │   ├── transcript.txt
│   │   ├── combat-log.txt
│   │   └── player-notes.md
│   └── session-002/
│       └── transcript.txt
└── sessions/
    ├── session-001.md
    └── session-002.md
```

首次写入前说明将使用的档案路径。已有档案时在原档案中继续维护，不得另建一份互相竞争的状态。保留用户已有格式和无关文件。

`sources/` 用于保存按回合分类的原始转写、战斗日志和玩家/DM 笔记；`sessions/` 保存可持续维护且推荐优先查看的 Markdown 战报主档；`exports/` 保存 Word、PDF 或 TXT 交付版本。未指定格式时默认生成 Markdown + Word + PDF；TXT 仅在用户要求时生成。用户明确不保留 Markdown 主档时，可以只生成 `exports/` 中的交付文件。原始 Campaign 资料不得放进 Skill 安装目录 `~/.codex/skills/dnd-replay`。

除非用户明确要求，不复制、移动、改名或修改原始转写。原始文件已经位于其他工作区路径时直接读取原位置，不强制迁入 `sources/`。可以在每回战报的元数据中记录来源文件名或相对路径，便于以后追溯。

## Campaign Profile

`campaign-profile.md` 保存长期背景和人物表，不用于记录每回剧情：

```markdown
# Campaign Profile

- 模组名称：
- 模组类型：长模组 / 短模组 / 单回冒险
- 模组简介：
- 当前进度：第几回 / 第几幕 / 第几章
- 玩家人数：
- DM 信息：可选
- 转写说话人约定：
- 战报交付格式：默认 Markdown + Word + PDF / 对话 / 单一格式 / 含 TXT 的自定义组合
- Markdown 主档：保留 / 不保留
- 文件版式偏好：可选

## 玩家角色

### 玩家名｜角色名
- 种族：
- 职业 / 子职业：
- 等级：
- 重要背景：

## 长期设定
- …
```

按照实际玩家角色数量重复角色小节。`玩家人数` 和角色名单不一致时，不自行补人或删人，应标记并请用户确认。

模组简介只属于背景资料。除非跑团记录另外证明玩家已经得知或经历，否则不得放入“本团已发生”或“玩家已知信息”。

首次建档时保存用户确认的交付格式。后续回合沿用该偏好；用户临时指定其他格式时，以本回明确要求为准，并只在用户表示要长期改变时更新 Profile。

## 首次处理所需的最低信息

Campaign 名称/类型、当前进度和可用的实际 PC 名单齐全后即可继续。可选信息缺失时写 `未提供`。如果名单不完整会造成关键行动错归角色，应先询问；否则保守记录为身份不明。

对于说话人不清晰的资料，还要确定以下一种情况：

- DM 和玩家已经分别标注；
- 只有“说话人 1/2/3”，需要推断或建立映射；
- 整份转写只有一个混合说话人；
- 用户同意自动根据上下文推断；
- 用户已经提供“说话人 → 玩家/角色”映射。

## Campaign Ledger

长模组的 `campaign-ledger.md` 应保持简洁，确保每次处理新回合前都能完整读取。它表示最近一次已处理回合结束时的状态。

```markdown
# CAMPAIGN LEDGER

## 当前进度
- 第 X 回 / 第 X 幕 / 第 X 章
- 最近更新：第 X 回

## 当前地点与路线
- 当前地点：
- 来自：
- 下一目的地：

## 任务
### 主线任务
- …
### 当前目标 / 未完成任务
- …
### 已完成任务
- …

## 角色状态
### 角色名
- 等级：
- HP / 状态：仅记录来源明确的回末状态
- 重要装备：
- 金钱：
- 重要关系 / 备注：

## NPC
### NPC 名称
- 状态：存活 / 死亡 / 失踪 / 被俘 / 已离开 / 未知
- 关系：
- 最后出现：第 X 回
- 已确认信息：

## 阵营与势力
### 友方势力
- …
### 敌对势力
- …

## 重要物品与资源
- 物品 / 金钱 → 当前持有者或“未确定”｜来源：第 X 回

## 已知线索
- [已确认] …｜首次：第 X 回｜更新：第 Y 回

## 玩家推测
- [推测] …｜提出：第 X 回｜状态：未验证 / 被否定 / 已证实

## 已确认秘密
- …｜确认：第 X 回

## 重要地点

## 连续性待确认
```

按 Campaign Profile 中的实际 PC 数量重复“角色状态”小节，不使用预设人数。

## Ledger 更新规则

- 对以后可能查询的事实保留“第 X 回”来源。
- 谜团解决后，从“未解谜团”移除，并在新战报剧情和合适的已确认栏目中记录答案及解决回合。
- 新证据出现时保留线索最初出现回合，不得覆盖首次来源。
- 物品转移、NPC 关系变化或任务状态变化后，Ledger 写当前状态；各回战报保留历史过程。
- 只有来源明确且回末仍有意义时，才延续临时 HP、法术位、状态或消耗品数据。
- 金钱可以按队伍或角色记录，但只使用明确来源；不得假设战利品平均分配。
- 如果用户只要求在对话中输出而未要求写文件，应附上界限清晰的新版 Ledger 区块，便于用户自行保存。

## 历史查询

先用 Ledger 定位相关回合，再核对对应战报。回答“什么时候、为什么、从哪里得到、第一次出现、谁拿到”等问题时，注明回合来源，并区分首次出现、首次确认和后续解决。
