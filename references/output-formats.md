# 战报输出格式与交付

用户要求生成文件，或首次建档尚未确认交付格式时读取本文件。

## 先确认格式

先检查当前提示和 Campaign Profile。用户已经指定格式时直接使用，不要重复询问。两处都没有格式偏好且任务需要写出战报文件时，在正式生成前询问一次：

> 默认同时生成 Markdown (`.md`)、Word (`.docx`) 和 PDF (`.pdf`)；其中 Markdown 是推荐阅读和长期维护的主档。你接受这个组合吗？如果只需要某一种格式或还需要 TXT，请直接告诉我。

如果用户只要求在对话中回答、查询历史或预览内容，不要为了文件格式阻塞任务；直接在对话中输出。用户接受推荐、说“都可以”或“常用格式都要”时，默认交付 Markdown + Word + PDF。用户强调打印时仍保留 Markdown 主档并导出 PDF；强调继续人工编辑时仍保留 Markdown 主档并导出 Word。用户明确只要一种格式或不要 Markdown 时，遵从其选择。

将长期偏好写入 Campaign Profile。后续回合沿用；一次性覆盖不自动改写长期偏好。

## 共同原则

- 所有格式必须来自同一份已经核对的内容，不得在不同导出版本中改变事实、行动归属或数值。
- 不得把 Markdown 文件改后缀伪装成 DOCX 或 PDF。
- 文件名使用稳定回合号，例如 `session-001.md`、`session-001.docx`、`session-001.pdf`、`session-001.txt`。
- Markdown 主档放入 `sessions/`；Word、PDF 与 TXT 放入 `exports/`。
- 用户指定其他位置或命名时遵从用户要求。
- 多格式交付完成后，按 Markdown、Word、PDF、TXT 的顺序列出每个可点击文件路径；Markdown 必须标注为“推荐阅读 / 内容主档”。
- 告知用户：Markdown 最接近核对后的原始结构，最适合长期查看和维护；Word/PDF 会受字体、分页和转换引擎影响，偶尔可能出现轻微版式偏差。

## Markdown (`.md`)

Markdown 是长模组推荐主档：

- 保留标题层级、引用、列表、表格、Emoji 与分隔线；
- 使用 UTF-8；
- 保持稳定的小节标题，便于后续查询与 Ledger 追溯；
- 不嵌入依赖本机绝对路径才能阅读的资源，除非用户明确只在本机使用。

## Word (`.docx`)

用户选择 Word 时，使用环境中可用的 Word/文档创建能力，并遵循其完整生成与验证流程：

- 使用真正的 `.docx` 文件；
- 使用标题样式而不是手工放大普通文本；
- 保留目录友好的标题层级、可读表格、引用块和分页；
- 避免标题单独落在页尾、表格越界、中文字体缺失和行距拥挤；
- 生成后渲染为页面图像或 PDF，逐页检查并修正布局。

如果当前环境没有可靠的 DOCX 生成与渲染能力，不得伪造文件；说明限制并询问用户是否接受 Markdown 或 TXT。

## PDF (`.pdf`)

用户选择 PDF 时，使用环境中可用的 PDF 创建与检查能力：

- 使用支持中文的嵌入字体；
- 设置适合屏幕阅读和打印的页边距、字号、行距与页码；
- 处理跨页表格、孤立标题、引用块和长 URL；
- 生成后逐页渲染检查，确认没有截断、乱码、空白页或溢出。
- 引用、旁注和名场面框必须处于正常文档流中；不得使用浮动文本框、绝对定位框或固定高度容器。
- ReportLab 中不得直接依赖带 `borderPadding` / `backColor` 的 `Paragraph` 充当引用框；这类样式可能只扩大绘制区域而未正确扩大流式布局高度，导致后文侵入背景框。使用无固定高度的一列表格包裹段落，或改用普通引用段落与左侧边线。
- 引用框与署名应作为一个不可拆散的小单元，但不得把可能跨页的大段内容整体 `KeepTogether`。长引用必须允许安全换页。
- 封面摘录和正文原话若重复，必须确认这是有意设计；不得为装饰自动复制正文引用。
- 视觉验证必须覆盖每一页，并专门复核至少一个长中文引用、一个跨页表格、页首页尾标题以及连续段落间距；发现内容重叠时必须修复后重新渲染。

若同时需要 Word 和 PDF，优先让两者来自同一份稳定的文档源并确保内容一致。当前环境不能可靠生成 PDF 时，不得提供损坏或伪造文件；说明限制并提供 Markdown/TXT 备选。

## 纯文本 (`.txt`)

TXT 必须是真正易读的纯文本版本，而不是残留大量 Markdown 语法：

- 使用 UTF-8；
- 标题改为清晰的纯文本分隔；
- Markdown 表格改为逐项标签或对齐良好的简单列表；
- 去掉链接语法、图片语法和仅用于排版的分隔标记；
- Emoji 可保留，但用户强调兼容性时改用普通文字；
- 保持八个固定栏目、队伍状态和结语的内容完整。

## 多格式

默认文件交付采用：

1. Markdown 作为可持续维护且推荐阅读的内容主档；
2. 从同一份已核对内容生成 Word 与 PDF；
3. 用户要求时另外生成 TXT；
4. 导出后检查标题、表格、引用、物品归属、金额、角色名和回末状态在各格式中一致；
5. 最终回复列出全部文件的准确路径，并提醒转换格式可能存在轻微排版差异。

用户明确不需要 Markdown 时，不强制交付 Markdown；Campaign Profile 与 Ledger 仍按长期档案规则维护，除非用户也明确要求不保存任何状态文件。
