# 转写分析与冒险重建

处理跑团转写、聊天记录、DM/玩家笔记或战斗日志时读取本文件。

## 资料清点

先判断每份资料的类型、覆盖回合或时间、可能作者和适用范围。多份资料重叠时不要假设它们同样完整：

- **会议转写 / 聊天记录**：最适合还原对话和事件顺序，但人名、术语和说话人容易出错。
- **战斗日志**：最适合确认骰点、伤害、资源和先攻，但通常缺少意图和剧情语境。
- **DM 笔记 / 模组资料**：适合确认专有名词和背景，不足以证明玩家实际经历过。
- **玩家笔记**：适合确认玩家知道什么、如何理解事件，但可能包含误记或推测。
- **角色卡**：适合确认某个时间点的角色构筑和状态，不足以证明本回采取过某个行动。

不同来源发生冲突时，列出冲突及各自来源。

## 说话人标注情况

### 已标注 DM 和玩家姓名

根据明确姓名、Campaign Profile 映射和桌上称呼绑定角色。除非出现新证据，否则全篇保持同一映射。

### 只有“说话人 1/2/3”

只有在上下文较强时才推断身份，例如出现角色名、他人称呼、角色专属能力、第一人称行动或稳定的发言模式。暂定映射始终保持暂定。讨论规则的人不一定是 DM。

### 整份文档只有一个说话人

将它视为混合音轨，其中可能同时包含 DM 叙述、多个玩家、NPC 台词、桌外讨论和规则说明。先按功能分类，再尝试判断身份：

- `[DM]`：明显的场景叙述或裁定；
- `[NPC]`：明显属于游戏内 NPC，但无法确认具体身份；
- `[玩家身份不明]`：可以确认是玩家发言，但不知道是哪名玩家；
- `[角色身份不明]`：可以确认是角色行动或台词，但无法绑定到具体 PC。

不得把唯一的转写标签绑定到录音文件的拥有者。身份不确定会影响角色栏目、物品归属或关键决定时，应先询问用户选择自动推断还是提供映射。用户同意自动推断后，仍要在最终战报中披露重要推断和遗留不确定项。

## 重建事件时间线

写战报前先建立内部事件表，不要直接从转写逐段压缩成正文。每个事件尽量记录：

- 场景、时间和地点；
- 行动者以及身份可信度；
- 行动或重要台词；
- 明确出现的检定、攻击、豁免、骰点与结果；
- 直接后果；
- 涉及的 NPC 或势力；
- 物品、金钱、消耗品变化及归属；
- 对线索、玩家推测或谜团的影响；
- 可以定位时的来源位置。

把事件归入有意义的场景，并排除排期、重复发言、规则查询、纯桌外闲聊和明显的转写噪声；桌外内容确实影响游戏决定时可以保留。

同一份事件表要服务三个不同层次：

1. **读者向剧情**：地点、目标、危险、选择、结果、台词和情绪转折。
2. **角色与战斗索引**：谁做了什么、关键成功或失败、资源与伤势。
3. **长期 Ledger**：当前状态、来源回合、线索、谜团和待确认项。

不要把第三层的字段化措辞直接复制到第一层。战报正文可以流畅叙述已确认事实，只在真正会误导读者的具体位置标记不确定。

## 事实判定

- 明确叙述且结果已经判定的行动：已确认事实。
- 玩家提出的猜想或角色计划：在剧情证实前属于玩家推测。
- 宣布“准备做”不等于已经完成。
- 宣布攻击不等于命中，除非记录给出或明确体现结果。
- 发现物品不等于某角色拥有物品，除非明确分配或拿取。
- 敌人到 0 HP 不一定等于死亡；以本团实际描述的昏迷、逃跑、死亡或未决为准。
- 记录没有提到某资源，不代表资源自动恢复或仍然保留。

任何容易误导读者的地方使用可见标记，例如 `玩家推测`、`身份不确定`、`数量不确定`、`结果未决` 或 `归属未确定`。不要给每条普通事实重复加 `[已确认]`，也不要让说话人歧义说明反复打断剧情；集中记录技术性歧义，只有影响行动者、结果、物品归属或推理结论时才在正文就地提示。

## 战斗重建

识别战斗开始和结束、敌人与可靠数量、双方目标、关键轮次、决定性检定、战术选择、状态、倒地/濒死/死亡、暴击/大失败、误伤、离谱事故和最终结果。

只有来源可靠时才保留精确骰点与伤害；否则记录定性结果并标记数字不确定。资料不完整时不得编造逐轮战斗日志，优先记录改变局势的事件和每名实际 PC 的有效贡献。

## 转写纠错

只有当前转写、用户说明、Campaign Profile 或既有本团档案共同指向唯一高置信度答案时，才可以把误识别词规范为正确的 D&D 术语、法术名、怪物名、NPC 名或地点名。

不得因为知道官方模组写法，就把本团明确说出的另一个词静默替换。例如转写稳定出现“一魂装置”，而只有模组知识提示它可能是“噬魂装置”时，正文应保留“一魂装置”，可在整理说明写“疑似某专有名词，待 DM 确认”。用户确认后再统一旧档案。

仍有多个可能时保留原词，并说明疑似某类专有名词但无法确认。高置信度纠错可以改善可读性，但必须在首次出现处保留必要的异文说明，不能把推测伪装成事实。

模组资料只能帮助辨认名称和背景。模组原文必须保留在 `模组背景`，不能进入 `本团已发生` 或 `玩家已知信息`，除非跑团资料另外提供支持。

## D&D 规则和 house rule

理解常见 D&D 术语和机制，但只记录本团实际裁定。如果 DM 的裁定与标准规则不同，不要修正已经发生的剧情结果；有必要时中性注明“本团似乎采用 DM 自定义判定 / house rule”。
